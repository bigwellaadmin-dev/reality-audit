# Using this skill without becoming the Hype-Man

Read this before deploying the skill in a classroom or feedback workflow.

## The recursive problem

Reality Audit teaches a learner not to let an agreeable AI do their thinking. This skill *is* an agreeable AI. The exact failure mode the framework is built to catch — **Relief, the good feeling that arrives when the machine agrees and your thinking quietly stops** — is one this skill can produce in you while it runs.

This is not a flaw in the skill. It is the framework folding back on itself. The fact that the irony is visible is what makes it useful.

## What using this skill well looks like

The skill extends your Reality Audit practice. It does not replace it.

- **You read what Claude generates, and you distrust the smooth parts.** The passage that feels most satisfying is the one to check. Fluency is not accuracy — here too.
- **You introduce friction Claude won't.** Claude is built to be helpful and agreeable. When it produces a clean, confident diagnosis of a student, ask it the question it skated past. Make it argue the other reading.
- **You have the Reflection conversation with a real human.** The skill can draft feedback. It cannot be the Difficult Human. That has to be you, or a colleague, or the student's peer.
- **You run the Academic Branch yourself.** The skill cannot watch a student reproduce something on a blank page. The closed-tool test is yours to run.
- **You treat Claude's diagnosis as a hypothesis, not a verdict.** When Mode 2 says "the problem started at Interaction," check whether that is what you see. It often will be. Sometimes it will not.

## What using this skill badly looks like

There is no version of the skill that prevents this. There is only your decision not to do it.

- **Reading Claude's feedback and feeling Relief.** That feeling is the framework's central warning, aimed at you. If the diagnosis lands easily and you stop thinking, you have just demonstrated the Hype-Man loop with yourself as the student.
- **Bulk-generating feedback you do not read.** The artefact exists. The teaching does not.
- **Letting Claude run Mode 1 with students you never speak to.** Claude is standing in for the friction. If the human friction never actually happens, the loop has produced compliance, not thinking.
- **Sending Claude's output to students without sharpening it.** Claude does not know your student. Generic feedback is the Generic Glow — technically fine, belongs to no one.

## The test

If you use this skill in any of the ways above, you have used Reality Audit to demonstrate the very loop it was built to break. The skill cannot stop you. The framework does not need to. Naming the loop is the whole point.

Use the skill the way you would want a student to use AI. Read what you receive. Distrust the relief. Argue with it. Make sure the thinking is still yours.

That is the test of whether you understand Reality Audit. The skill is one of the places you will be tested.
